# คู่มือทำความเข้าใจทั้งระบบ Trash & Toilet Japan

คู่มือนี้อธิบายว่าโปรเจกต์ถูกสร้างขึ้นอย่างไร แต่ละไฟล์มีหน้าที่อะไร และเมื่อผู้ใช้กดปุ่มหนึ่งครั้ง ระบบทำงานต่อกันอย่างไร เหมาะสำหรับอ่านหลังจากโปรเจกต์ทำงานได้แล้ว

---

## 1. โปรเจกต์นี้แก้ปัญหาอะไร

ระบบช่วยนักท่องเที่ยวค้นหาห้องน้ำและถังขยะ โดยข้อมูล Marker มาจาก Database ของเราเอง ส่วน OpenStreetMap เป็นเพียงภาพพื้นแผนที่

ผู้ใช้ทั่วไปสามารถ:

- สมัครสมาชิกและเข้าสู่ระบบ
- ดูสถานที่บนแผนที่
- ใช้ GPS ค้นหาสถานที่ใกล้ตัว
- กรองห้องน้ำ ถังขยะ และระยะทาง
- เสนอสถานที่ใหม่พร้อมรูปภาพ
- รายงานข้อมูลสถานที่ผิด
- เปลี่ยนรูปโปรไฟล์และธีมหน้าจอ

Admin สามารถ:

- เพิ่มสถานที่ที่ active ทันที
- อนุมัติหรือปฏิเสธคำขอจาก Member
- ดูและลบสถานที่
- จัดการ Report
- ใช้ Profile, Logout, รูปโปรไฟล์ และ Theme เหมือน Member

---

## 2. เทคโนโลยีที่ใช้จริง

### Frontend

- React + JavaScript สร้างหน้าจอ
- React Router เปลี่ยนหน้าโดยไม่โหลดเว็บใหม่
- Tailwind CSS จัดหน้าตา
- Axios เรียก Backend API
- react-geolocated อ่าน GPS
- React Leaflet แสดงแผนที่
- OpenStreetMap เป็น Base Map
- Lucide React แสดง Icon

### Backend

- Node.js รัน JavaScript ฝั่ง Server
- Express สร้าง API
- Prisma ORM ติดต่อ Database
- MariaDB เป็น Database ของโปรเจกต์ปัจจุบัน
- bcrypt hash และตรวจรหัสผ่าน
- JWT สร้าง Token เข้าสู่ระบบ
- Zod ตรวจรูปแบบข้อมูล
- Multer รับไฟล์รูปภาพ

### เครื่องมือพัฒนา

- Prisma Studio ดูข้อมูลใน Database
- Postman ทดสอบ API ทีละ Route
- API Smoke Test ทดสอบ Flow หลักอัตโนมัติ
- Cloudflare Tunnel สร้าง HTTPS URL ชั่วคราวสำหรับแชร์เว็บ

## 6. Database ทำงานอย่างไร

อ่าน `BackEnd/prisma/schema.prisma`

### User

เก็บผู้ใช้งาน:

- `id` รหัสผู้ใช้
- `name` ชื่อ
- `email` อีเมลที่ห้ามซ้ำ
- `password` รหัสผ่านที่ hash แล้ว
- `avatarUrl` URL รูปโปรไฟล์
- `role` เป็น member หรือ admin

### Place

เก็บสถานที่:

- `name`, `type`, `address`
- `imageUrl` รูปสถานที่
- `latitude`, `longitude` พิกัด
- `status` สถานะ
- `createdById` ผู้สร้าง

### Report

เก็บรายงานข้อมูลผิด:

- `reason`, `description`
- `evidenceImageUrl` URL รูปหลักฐานชั่วคราว
- `status`
- `placeId` สถานที่ที่ถูกรายงาน
- `reporterId` ผู้รายงาน

### Relationship

```text
User 1 คน → สร้าง Place ได้หลายรายการ
User 1 คน → ส่ง Report ได้หลายรายการ
Place 1 แห่ง → มี Report ได้หลายรายการ
```

เมื่ออ่าน Controller แล้วเห็น `prisma.user`, `prisma.place` หรือ `prisma.report` ให้กลับมาดู Model ตรงนี้

## 7. Backend รับ Request อย่างไร

ไฟล์เริ่มต้นคือ `BackEnd/src/server.js`

ลำดับการทำงาน:

```text
Request เข้ามา
→ CORS ตรวจ Origin
→ express.json อ่าน JSON
→ /uploads เปิดไฟล์รูป
→ เลือก Route ตาม URL
→ Middleware
→ Controller
→ Prisma
→ MariaDB
→ ส่ง JSON Response
```

`server.js` ยังเสิร์ฟไฟล์ React จาก `FrontEnd/dist` เมื่อ Build แล้ว ทำให้ Frontend และ Backend ใช้ URL เดียวกันตอนแชร์เว็บ

## 8. Route, Middleware และ Controller ต่างกันอย่างไร

### Route

ไฟล์ใน `BackEnd/src/routes` รับ URL และเรียงขั้นตอน

ตัวอย่าง:

```js
router.post("/", authMiddleware, uploadPlaceImage, validate(schema), createPlace);
```

แปลว่า:

```text
รับ POST
→ ตรวจ Login
→ รับรูป
→ ตรวจข้อมูล
→ สร้าง Place
```

### Middleware

- `authMiddleware.js` ตรวจ JWT และสร้าง `req.user`
- `adminMiddleware.js` ตรวจว่า role เป็น admin
- `validateMiddleware.js` ใช้ Zod ตรวจข้อมูล
- `uploadMiddleware.js` รับและบันทึกรูป

### Controller

ไฟล์ใน `controllers` มี Logic หลัก เช่น ค้นหา User, สร้าง Place, คำนวณระยะ และเปลี่ยน Report status

## 9. Register/Login Flow

### สมัครสมาชิก

```text
RegisterPage.jsx
→ api.post('/auth/register')
→ authRoutes.js
→ registerSchema
→ authController.register
→ bcrypt.hash(password)
→ prisma.user.create
→ MariaDB
```

รหัสผ่านจริงไม่ถูกเก็บใน Database มีเพียง Hash

### เข้าสู่ระบบ

```text
LoginPage.jsx
→ AuthProvider.login
→ POST /api/auth/login
→ bcrypt.compare
→ jwt.sign
→ Frontend เก็บ token ใน localStorage
→ loadUser เรียก GET /api/users/me
```

Axios interceptor ใน `services/api.js` นำ Token ไปใส่ Header อัตโนมัติ:

```text
Authorization: Bearer TOKEN
```

## 10. AuthProvider และ ProtectedRoute

อ่าน:

```text
hooks/authContext.js
→ hooks/AuthProvider.jsx
→ hooks/useAuth.js
→ components/ProtectedRoute.jsx
```

`AuthProvider` เก็บ `user` ไว้ให้ทุกหน้าใช้ร่วมกัน และมีฟังก์ชัน Login, Logout และ Reload User

`ProtectedRoute` ป้องกันหน้าที่ต้อง Login และตรวจ Admin Route

```text
ไม่มี User → ไป /login
เป็น Member แต่เข้า Admin Route → ปฏิเสธ
เป็น Admin → ผ่าน
```

## 11. Place Flow

### Member เพิ่มสถานที่

```text
AddPlacePage
→ PlaceForm
→ GPS/กรอกพิกัด/เลือกรูป
→ FormData
→ POST /api/places
→ authMiddleware
→ Multer
→ Zod
→ placeController.createPlace
→ Backend บังคับ status = pending
```

### Admin เพิ่มสถานที่

ใช้ Flow เดียวกัน แต่ Controller อ่าน `req.user.role` แล้วตั้ง `status = active`

### Admin อนุมัติ Member

```text
AdminPendingPlacesPage
→ GET /api/places/pending
→ PATCH /api/places/:id/status
→ status = active หรือ rejected
```

### ลบ Place

```text
DELETE /api/places/:id
→ ลบ Place
→ Report ถูกลบตาม relation แบบ Cascade
→ ลบไฟล์รูปออกจาก uploads
```

## 12. รูปภาพทำงานอย่างไร

### รูปสถานที่

```text
input type=file
→ Frontend สร้าง FormData field ชื่อ image
→ Multer บันทึกไฟล์ใน BackEnd/uploads
→ Database เก็บเพียง /uploads/ชื่อไฟล์
→ Express เปิด URL /uploads
→ Frontend ใช้ getAssetUrl แสดงรูป
```

### รูปโปรไฟล์

```text
ProfilePage แตะรูป
→ FormData field ชื่อ avatar
→ PATCH /api/users/me/avatar
→ Multer บันทึกรูป
→ User.avatarUrl เก็บ URL
→ reloadUser โหลด User ใหม่
```

เมื่อเปลี่ยน Avatar ระบบลบไฟล์เดิมหลังบันทึกรูปใหม่สำเร็จ

### รูปหลักฐาน Report

```text
ReportPage เลือก/ถ่ายรูป
→ FormData field ชื่อ evidence
→ POST /api/reports
→ Multer เก็บไฟล์ใน uploads
→ Report.evidenceImageUrl เก็บ URL ชั่วคราว
→ AdminReportDetailPage แสดงรูป
→ Admin จัดการ Report หรือ Place ถูกลบ
→ Backend ลบไฟล์หลักฐาน
```

## 14. GPS และการกรอกที่อยู่

`react-geolocated` ขอพิกัดจริงจาก Browser

```text
ผู้ใช้กดตำแหน่งปัจจุบัน
→ Browser ขอ Location Permission
→ ได้ latitude/longitude
→ Map เลื่อนไปตำแหน่งผู้ใช้
```

หน้าเพิ่มสถานที่เรียก `services/locationService.js` เพื่อ Reverse Geocoding:

```text
latitude/longitude
→ Nominatim ของ OpenStreetMap
→ ได้ข้อความที่อยู่
→ เติมลงช่อง Address
```

GPS บนมือถือควรเปิดเว็บผ่าน HTTPS

## 15. Search และ Filter

หน้า `SearchPage.jsx` เริ่มต้นที่ระยะ 500 เมตร

```text
รับ GPS
→ GET /api/places/nearby
→ Backend คำนวณระยะด้วย latitude/longitude
→ กรองไม่เกิน radius
→ Frontend กรอง type และคำค้นต่อ
→ PlaceCard แสดงผล
```

หน่วยที่ส่งเข้า Backend เป็นกิโลเมตร:

```text
500 เมตร = 0.5 กิโลเมตร
1000 เมตร = 1 กิโลเมตร
```

เลือก “ทั้งหมด” จะใช้ `GET /api/places` โดยไม่จำกัดระยะ

## 16. Report Flow

### Member ส่ง Report

```text
PlaceDetailPage
→ ReportPage
→ เลือกเหตุผล + รายละเอียด + รูปหลักฐาน
→ POST /api/reports แบบ FormData
→ uploadReportEvidence รับ field evidence
→ Backend ตรวจ Place

```

### Admin จัดการ Report

```text
AdminReportsPage
→ GET /api/reports?status=pending
```

- ปฏิเสธรายงาน → Report status เป็น rejected
- ดำเนินการลบ → ลบ Place, รูปสถานที่, รูปหลักฐาน และ Report ที่เกี่ยวข้อง

## 20. Axios และ Environment

`FrontEnd/src/services/api.js` สร้าง Axios instance เพียงตัวเดียว

Development:

```env
VITE_API_URL=http://localhost:3000/api
```

```env
VITE_API_URL=http://IP_ของคอม:3000/api
```

```env
VITE_API_URL=/api
```

ค่า `/api` ทำให้ Frontend ใช้ Domain เดียวกับ Backend และ Tunnel ได้โดยไม่ต้องรู้ URL ล่วงหน้า

## 23. วิธี Build และแชร์ผ่าน HTTPS

Build Frontend:

```powershell
cd FrontEnd
npm run build
```

ไฟล์จะถูกสร้างใน `FrontEnd/dist` และ Backend จะเสิร์ฟไฟล์เหล่านี้

ข้อควรระวัง:

- ลิงก์ Quick Tunnel เป็นลิงก์ชั่วคราว
- ปิดคอมหรือปิด Process แล้วเว็บหยุด
- API และรูปที่ตั้งใจให้เว็บใช้จะถูกเปิดผ่านอินเทอร์เน็ต

## 25. วิธีไล่ Bug แบบมือใหม่

### Frontend กดแล้ว Error

1. เปิด Browser DevTools
2. ดู Console
3. ดู Network ว่า API ใดแดง
4. ดู Status เช่น 400, 401, 403, 404, 500
5. ตาม URL ไปหา Route และ Controller

### ความหมาย Status ที่พบบ่อย

- `400` ข้อมูลไม่ผ่าน Zod หรือไฟล์ผิด
- `401` ไม่มี Token หรือ Token หมดอายุ
- `403` ไม่มีสิทธิ์ Admin
- `404` ไม่พบ Route หรือข้อมูล
- `500` Backend/Database มี Error

### ตามโค้ดจาก URL

```text
/api/places
→ server.js ใช้ placeRoutes
→ placeRoutes.js หา method/path
→ อ่าน Middleware จากซ้ายไปขวา
→ อ่าน Controller ตัวสุดท้าย
→ ดู Prisma Model ที่ถูกเรียก
```

## 26. Logic สำคัญที่ห้ามลืม

- Member สร้าง Place → pending
- Admin สร้าง Place → active
- Map แสดงเฉพาะ active
- OpenStreetMap เป็น Base Map เท่านั้น
- Marker มาจาก Database
- Report ใหม่ → pending
- Admin เปลี่ยน Report เป็น resolved/rejected หรือลบ Place ตามงาน
- Password ต้องเก็บเป็น bcrypt hash
- JWT ต้องส่งแบบ Bearer Token
- Backend เป็นผู้ตัดสิน role/status ไม่เชื่อค่าจาก Frontend
- รูปจริงอยู่ใน uploads ส่วน Database เก็บ URL
- Report ต้องมีรูปหลักฐาน และรูปจะอยู่ชั่วคราวจน Admin จัดการ
- Login ใช้ Email/Password ไม่มี Google Login
- GPS บนมือถือควรใช้ HTTPS

## 27. สรุป Flow ใหญ่ที่สุด

```text
ผู้ใช้เปิด React
→ Router เลือก Page
→ ผู้ใช้กดปุ่ม
→ Page/Component เรียก Axios
→ Axios แนบ JWT
→ Express server.js รับ Request
→ Route เลือกเส้นทาง
→ Auth/Admin ตรวจสิทธิ์
→ Multer รับรูป (ถ้ามี)
→ Zod ตรวจข้อมูล
→ Controller ทำ Logic
→ Prisma ติดต่อ MariaDB
→ Backend ส่ง JSON
→ React เปลี่ยน State
→ หน้าจอแสดงข้อมูลใหม่
```

ถ้าเข้าใจเส้นทางนี้ จะสามารถอ่านและแก้โปรเจกต์ทั้งระบบได้ โดยไม่จำเป็นต้องจำทุกบรรทัด
