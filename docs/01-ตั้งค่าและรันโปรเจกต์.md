# คู่มือที่ใช้กับโปรเจกต์ปัจจุบัน

คู่มือต่อจากนี้ให้ยึดโค้ดจริงใน `BackEnd` ไม่ยึดตัวอย่างเก่าที่ใช้ CommonJS หรือ Prisma 6

## รูปแบบโค้ดปัจจุบัน

- Node.js แบบ ES Module เพราะ `package.json` มี `"type": "module"`
- ใช้ `import` / `export` เท่านั้น ไม่ใช้ `require()`
- Express 5
- Prisma 7 และ generated client อยู่ที่ `generated/prisma`
- Database ใช้ MariaDB ผ่าน `@prisma/adapter-mariadb`
- การเชื่อมต่อ MySQL 8 แบบ local เปิด `allowPublicKeyRetrieval: true` ใน `src/lib/prisma.js` เพื่อรองรับ `caching_sha2_password`
- ใช้ Zod ตรวจ Body, Params และ Query ก่อนเข้า Controller
- โหลด `.env` ด้วย `import "dotenv/config"`
- Server ใช้ `process.env.PORT` และ fallback เป็น `5000` แต่ `.env` ปัจจุบันกำหนด `3000`
- React Frontend เรียก Backend ได้ผ่าน CORS โดยค่าเริ่มต้นใช้ `http://localhost:5173`

## เตรียม Database ก่อนเปิดโปรเจกต์

โปรเจกต์นี้ใช้ MariaDB/MySQL ตลอดทั้งระบบ:

- `schema.prisma` ใช้ `provider = "mysql"`
- `src/lib/prisma.js` ใช้ `PrismaMariaDb`
- package ใช้ `@prisma/adapter-mariadb`

เริ่มจากคัดลอก `BackEnd/.env.example` เป็น `BackEnd/.env` แล้วใส่ค่า `DATABASE_HOST`, `DATABASE_PORT`, `DATABASE_USER`, `DATABASE_PASSWORD` และ `DATABASE_NAME` ให้ตรงกับฐานข้อมูลจริง

จากนั้น `BackEnd/src/lib/prisma.js` จะอ่านค่าเหล่านั้นเพื่อสร้าง adapter:

```js
const adapter = new PrismaMariaDb({
  host: process.env.DATABASE_HOST,
  port: Number(process.env.DATABASE_PORT || 3306),
  user: process.env.DATABASE_USER,
  password: process.env.DATABASE_PASSWORD,
  database: process.env.DATABASE_NAME,
  allowPublicKeyRetrieval: true,
  connectionLimit: 5,
});
```

บรรทัด `allowPublicKeyRetrieval: true` รองรับ MySQL 8 บางชุดที่ใช้ `caching_sha2_password` ผ่านการเชื่อมต่อ local ที่ไม่ได้ใช้ TLS ถ้าขาดบรรทัดนี้ Prisma อาจเชื่อมต่อฐานข้อมูลไม่ได้ แม้ค่าภายใน `.env` จะถูกต้อง

โปรเจกต์นี้ตกลงใช้ MariaDB/MySQL แล้ว ไม่ต้องเปลี่ยนเป็น PostgreSQL ในขั้นตอนถัดไป

## ตรวจ Database และเตรียมบัญชี Admin

สมัครสมาชิกจากหน้า Register ก่อน แล้วรัน `npx prisma studio` ในโฟลเดอร์ `BackEnd` เพื่อเปิดตาราง `User` และเปลี่ยน `role` จาก `member` เป็น `admin` สำหรับทดสอบหน้าผู้ดูแล


## เปิด Backend และ Frontend

เปิด Backend ใน Terminal แรก:

```powershell
cd BackEnd
npm run dev
```

ต้องเปิด Terminal นี้ค้างไว้ เพราะ Frontend ต้องส่ง request มาที่ `http://localhost:3000/api` ถ้า Backend หยุด หน้าเว็บยังเปิดได้ แต่ Register, Login และข้อมูลจาก Database จะใช้งานไม่ได้

เปิด Frontend ใน Terminal ที่สอง:

```powershell
cd FrontEnd
npm run dev
```

จากนั้นเปิด `http://localhost:5173/login` และใช้บัญชีตัวอย่างจากขั้นตอนก่อนหน้า

## คำสั่ง Prisma ที่ใช้ระหว่างพัฒนา

คำสั่งต่อไปนี้ให้รันภายในโฟลเดอร์ `BackEnd`

สร้าง Prisma Client ใหม่หลังแก้ schema:

```powershell
npx prisma generate
```

ตรวจสอบ schema:

```powershell
npx prisma validate
```

สร้าง migration:

```powershell
npx prisma migrate dev --name ชื่อ_migration
```

เปิด Prisma Studio:

```powershell
npx prisma studio
```

## แก้ปัญหา Login ไม่ได้

Login มีเส้นทางการทำงาน `Frontend → Backend → Prisma → Database` จึงควรตรวจตามลำดับเดียวกัน:

1. ตรวจว่า Terminal ของ Backend ยังรันอยู่ที่ `http://localhost:3000`
2. ตรวจว่า `FrontEnd/.env` มี `VITE_API_URL=http://localhost:3000/api`
สมัครสมาชิกและตรวจข้อมูลใน Prisma Studio เพื่อยืนยันว่า Backend ติดต่อ Database ได้
4. ถ้า seed ไม่ผ่าน ให้ตรวจค่าฐานข้อมูลใน `BackEnd/.env`
5. ตรวจว่า `BackEnd/src/lib/prisma.js` มี `allowPublicKeyRetrieval: true`
6. หลังแก้แล้วให้หยุดและเปิด Backend ใหม่ด้วย `npm run dev`

ถ้าพบข้อความต่อไปนี้:

```text
RSA public key is not available client side
pool timeout: failed to retrieve a connection from pool
```

หมายถึงปัญหาอยู่ระหว่าง Prisma กับ MySQL ไม่ได้เกิดจากหน้า Login ให้ย้อนกลับไปตรวจขั้นตอน Database แล้ว Restart Backend

`src/app.js` ไม่มีอยู่ในโปรเจกต์ เพราะ Express app และจุดเริ่ม Server รวมอยู่ใน `src/server.js`

## ลำดับการทำงานปัจจุบัน

```text
Frontend/Postman
→ server.js
→ routes
→ auth/admin middleware
→ Multer ถ้า Request มีรูป
→ Zod validation
→ controller
→ Prisma
→ MariaDB
```

อ่านต่อที่ [ลำดับอ่านโค้ด Backend](03-ลำดับอ่านโค้ด-Backend.md)

## ระบบรูปปัจจุบัน

- `POST /api/places` รับ `multipart/form-data` field `image`
- `PATCH /api/users/me/avatar` รับ field `avatar`
- `POST /api/reports` รับ field `evidence`
- รูป Report เป็นหลักฐานชั่วคราวและลบเมื่อ Admin จัดการเสร็จ
- Login ปัจจุบันใช้ Email/Password ไม่มี Google Login
